Copilot Search in GitHub Docs

Role: Product design: discovery, concept prototyping, interaction design, and launch refinement
Timeline: July 2024-May 2025

Users struggled to find relevant answers through Docs search, leaving them to sort through documentation rather than get the help they needed.

I joined to translate card-sort findings into a navigation refresh. Through stakeholder interviews, a review of usage data and public feedback, and an audit of the experience, I identified a broader opportunity: help people get answers, not just navigate articles. Users were already turning to external search engines and AI tools when Docs search fell short. I proposed bringing Copilot into that experience, and partnered with the product manager to explore the approach.

Working with Docs product and engineering, Copilot Design, and Customer Success Engineering, I shaped the experience from early exploration through staff testing and public preview. The result was an optional AI assistant within search, designed to help people synthesize answers while keeping source documentation and traditional article results within reach.

Making the problem clear

As a new member of the team, I treated Docs stakeholders as design partners. I interviewed leadership, content writers, and engineers about customer feedback and their direct experiences helping users. I reviewed usage signals alongside stakeholder and public feedback. I also manually reviewed search feedback on X/Twitter, Reddit, and GitHub Discussions, then built a screen inventory and analyzed key workflows.

The feedback suggested a pattern: novices could give up when results missed the mark, while experienced users worked around Docs search with external search engines or AI tools. The audit also surfaced dated typography and illustrations, but the larger opportunity was finding answers. Users' growing comfort with AI made Copilot a direction worth testing, rather than assuming navigation changes alone would solve the problem.

Stress-testing where AI belonged

My initial instinct was to put AI-generated summaries in the search dialog. But users who had learned to bypass Docs search might never discover them. An assistant embedded in an article could meet those readers where they already were.

The product manager and I brainstormed alternatives, and I rapidly prototyped them for testing with the Docs team. I explored article-level assistance and persistent controls, including for readers landing directly on anchored sections. That improved visibility, but an ever-present assistant also risked competing with the documentation.

Through prototype testing and reviews with Docs and Copilot Design, we built alignment around the search dialog as the primary path. It met people where they expressed a question, including new GitHub users already using AI to code who had not yet formed habits around external search.

Search first, Copilot second

I shaped the hierarchy around a deliberate choice: conventional article matches came first, with Ask Copilot as a secondary action. People could still press Enter or view all articles; generating an answer was an explicit choice, not a replacement for search.

With the primary flow agreed, I worked in fast feedback loops with engineering to refine the look, feel, and behavior across dozens of possible states. Answers linked back to documentation so readers could verify details and keep learning. I worked through loading, error, and return-to-results states, including declining out-of-scope questions while preserving a useful path back to Docs search.

Shipped

A controlled A/B rollout showed that visitors exposed to the redesigned search experience were twice as likely to interact with search. Among visitors who rated a Copilot answer, the majority rated the answer positively. Based on these signals and staged testing, the experience rolled out to 100% of GitHub Docs visitors.

The biggest design decision wasn't how the chat looked. It was giving AI a clear, limited job: help when someone needs an answer synthesized from documentation, and stay out of the way when an article is enough.
